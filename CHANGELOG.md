## [1.6.0] — 2026-09-17

Фаза «Щит» ([ROADMAP](ROADMAP.md)): дорогие ручки получили лимит, а релиз
научился выкатываться сам — по тегу, без ручного доступа к серверу.

### Added

- **Ограничение частоты запросов** (`app/ratelimit.py`, middleware
  `rate_limit`): скользящее окно на клиента для `POST /api/quiz/evaluate`
  (30 расчётов в минуту) и `?refresh=1` у ленты, погоды и моря (6 за
  5 минут). Каталог, health, статика и чтение из кэша лимит не
  расходуют — обычный просмотр остаётся бесплатным. Счётчики в памяти
  процесса (БД у проекта нет), число отслеживаемых клиентов ограничено
  `RATE_LIMIT_MAX_KEYS` — самые давние ключи вытесняются.
- **Честный отказ `429`**: `Retry-After` + заголовки `X-RateLimit-Limit`,
  `-Remaining`, `-Reset` на лимитируемых ручках (и на успехе, и на
  отказе), `detail` вида «слишком часто: попробуйте через 40 с».
  Защитные заголовки и CSP на отказе сохраняются: middleware
  `security_headers` стал внешним слоем.
- **`TRUST_PROXY`**: за своим Caddy реальный адрес клиента — первый
  в `X-Forwarded-For` (compose передаёт `1`), иначе все гости делили бы
  один лимит на IP контейнера. По умолчанию (`0`) считается адрес
  соединения — чужому клиенту заголовок верить нельзя.
- **`static/rate-limit.js`** (UMD, 10 JS-тестов): `Retry-After` →
  «попробуйте через 5 минут» с русскими формами, мусор в заголовке не
  порождает «через undefined». Фронт больше не показывает сырой
  «429 Too Many Requests»: квиз и кнопка «Обновить» в новостях говорят
  по-человечески, а кнопка после 429 снова рабочая.
- **Автодеплой по тегу** (`.github/workflows/deploy.yml`): `git push --tags`
  → preflight (`ruff check` + `pytest` + `node --test`) → по SSH
  `deploy/deploy.sh <тег>`: обновление исходников, `docker compose up -d
  --build`, ожидание healthy контейнера и **сверка версии** из
  `/api/health` с ожидаемой. Запуск вручную (`workflow_dispatch`) с любым
  ref — им же делается откат. Одновременные выкаты встают в очередь.
  Сторонних экшенов нет: только `actions/*` и `ssh`; хост, пользователь
  и ключ — в секретах GitHub (таблица — в [docs/deploy.md](docs/deploy.md)).
- `deploy/deploy.sh` — выкат, который можно запустить и руками
  (`./deploy/deploy.sh v1.6.0`, `APP_DIR=…`, `HEALTH_TIMEOUT=…`).
- Тесты: 304 → **350 Python** (+46: `tests/test_ratelimit.py` — 35,
  плюс конфиг- и ассет-тесты), 68 → **78 JS** (+10).

### Changed

- Версия 1.5.0 → **1.6.0**; кэш PWA `crimea-gid-v1.6.0`.
- Порядок middleware: `security_headers` объявлен последним, то есть
  стал **внешним** слоем — иначе short-circuit из `rate_limit` отдавал бы
  429 без CSP и `nosniff`.
- `docker-compose.yml` и `.env.example`: ручки `RATE_LIMIT_ENABLED`,
  `RATE_LIMIT_QUIZ`, `RATE_LIMIT_REFRESH`, `TRUST_PROXY`.
- CI: `node --check static/rate-limit.js`; теги `v*` тоже гонят полный CI
  (чтобы релиз не выкатывался вслепую).

### Docs

- `docs/api.md`: раздел «Ограничение частоты запросов» (таблица лимитов,
  заголовки, 429, `TRUST_PROXY`) и код 429 в таблице ошибок.
- `docs/deploy.md`: «Автодеплой по тегу» — схема, таблица секретов,
  подготовка ключа, откат; новые переменные в таблице `.env`.
- `docs/architecture.md`: `ratelimit.py` и `rate-limit.js` в компонентах,
  лимиты в разделе «Безопасность», выкат в «Развёртывании».
- `docs/development.md`: модули тестов, счётчики, строка «как расширять»
  для нового лимита и шага деплоя, отладка 429 в dev, релиз через тег.
- README: версия 1.6.0, лимиты и автодеплой в возможностях, новые env
  и файлы в структуре, счётчики тестов.

## [1.5.0] — 2026-09-17

Фаза «Карта» ([ROADMAP](ROADMAP.md)): поверх офлайн SVG-схемы появился
опциональный интерактивный слой на Leaflet — с приближением, тайлами
OpenStreetMap и теми же маркерами/маршрутом, что и на схеме.

### Added

- **Интерактивная карта** (опциональный слой): по умолчанию пользователь
  видит знакомую SVG-схему (работает без сети, не тянет тайлы), кнопка
  «🛰 Спутник/карта» в тулбаре карты поднимает Leaflet с OSM-тайлами.
  Leaflet (1.9.4) лежит локально в `static/vendor/` — без CDN, без npm-сборки,
  строгая CSP `script-src 'self'` не ослабляется.
- `static/leaflet-map.js` (UMD, 5 JS-тестов): обёртка над Leaflet с ленивой
  загрузкой (скрипт/стили добавляются в DOM в момент переключения слоя,
  не увеличивая холодную загрузку на ~160 Кб), кастомными цветными маркерами
  в стиле SVG-схемы, маршрутом плана пунктиром и нумерованными остановками.
- Переключатель слоёв с подписями: «работает без сети» для схемы,
  «интерактивная карта · тайлы OpenStreetMap» для спутника.
- **Деградация при ошибке загрузки**: если Leaflet не поднялся или тайлы
  недоступны — пользователь автоматически возвращается на SVG-схему
  и видит тост, вместо пустого квадрата.
- CSP: `img-src` и `connect-src` расширены только на `https://tile.openstreetmap.org`
  (тайлы), остальные директивы не тронуты.
- Тесты: 304 Python (+8), 68 JS (+5). Новые ассет-тесты: модуль UMD и
  подключён к каркасу/прекэшу, вендоры на месте без CDN-ссылок, дефолт
  — SVG, есть откат при ошибке, цвета маркеров синхронизированы с SVG.

### Changed

- Версия 1.4.0 → **1.5.0**; кэш PWA `crimea-gid-v1.5.0`.
- `state.mapLayer` (по умолчанию `"svg"`) — состояние переключателя слоя
  (кроме активного слоя, состояние не сохраняется: при перезагрузке
  пользователь возвращается к офлайн-схеме, как ожидается в PWA).
- Маршрут плана (`state.mapShowPlan`) работает одинаково на обоих слоях:
  фильтр по тегам, «Мой план» и избранное сразу применяются и к SVG,
  и к интерактивной карте при переключении.

### Docs

- README: версия 1.5.0, в возможностях — интерактивная карта по желанию.
- `docs/api.md`: версия в health-примере.
- `docs/architecture.md`: CSP обновлена на OSM-тайлы для опциональной карты.

## [1.4.0] — 2026-09-17

Фаза «По часам» ([ROADMAP](ROADMAP.md)): в карточке города появился
почасовой прогноз — и «сейчас» в нём не врёт даже на ответе из кэша.

### Added

- **Почасовой прогноз** (`hourly` в `/api/weather`, `static/hourly.js`):
  температура, WMO-код и вероятность осадков на 24 часа вперёд. Сервер
  только нарезает окно от текущего часа города сравнением ISO-строк —
  времена остаются локальными для курорта, без конвертации в пояс
  клиента (naive→UTC сдвигал бы час назад).
- **Окно показывает клиент** (`Hourly.next`): ответ живёт в кэше до
  `WEATHER_TTL`, поэтому час «сейчас» отсчитывается в браузере по
  крымскому времени (UTC+3, как в `open-now.js`). Турист из Москвы
  и из Екатеринбурга видит одинаковую строку. Прогноз, целиком
  ушедший в прошлое, даёт пустое окно — фронт прячет блок, а не
  показывает вчерашние часы.
- Блок «По часам» в карточке города: 12 часов с подписью «сейчас»
  у текущего, «💧40%» при вероятности осадков от 30%, горизонтальная
  прокрутка на узких экранах. Раскрытие — нативное `<details>`:
  без JS-обработчиков (CSP `script-src 'self'`), работает с клавиатуры
  и читается скринридером.
- Тесты: 272 → **298 Python**, 48 → **63 JS**. Новое: часовое окно
  (старт с текущего часа, лимит, отставшая модель, короткие массивы,
  мусор вместо чисел), API-тест на `hourly` и 15 JS-тестов окна
  (крымское время, «сейчас» ровно один раз и первым, полночь,
  устаревший кэш, размер окна, порог осадков).

### Changed

- Версия 1.3.0 → **1.4.0**; кэш PWA `crimea-gid-v1.4.0`.
- `_number()` в `weather.py`: `null`, строки и `bool` в ответе модели
  дают `null`, а не падение — как и в морском сервисе.
- CI: `node --check static/hourly.js`; в документации команда проверки
  синтаксиса заменена на обход `static/*.js` (список модулей больше
  не дрейфует).

### Docs

- `docs/api.md`: поля `hourly[]`, правило локального времени и граница
  ответственности «сервер нарезает — клиент показывает».
- `docs/architecture.md`: часовое окно в потоке погоды, `hourly.js`
  в компонентах фронта.
- `docs/development.md`: `hourly.test.js` в таблице JS-тестов, `hourly`
  в описании `test_weather.py`, строка «как расширять» для нового поля
  прогноза, счётчики.
- README: блок возможностей, структура, счётчики тестов.

## [1.3.0] — 2026-09-17

Фаза «Купальня» ([ROADMAP](ROADMAP.md)): погодный виджет научился
отвечать на главный летний вопрос — «можно ли купаться» — и честно
молчать, если модель не покрывает точку.

### Added

- **Море и купальный индекс** (`app/services/marine.py`,
  `GET /api/sea`): температура поверхности воды и волна по 15 приморским
  курортам из Open-Meteo Marine (без ключа). Вердикт считает **сервер** —
  он не зависит от часового пояса устройства, и все клиенты видят один
  ответ: волна ≥1,5 м «купаться опасно», ≥1,0 м «купаться не стоит»,
  иначе по воде 23/20/16 °C «комфортно / можно / прохладно — для
  закалённых / холодно». Волна важнее температуры: безопасность выше
  удовольствия.
- **Вердикт по «сырым» значениям**: 22.6 °C показывается как `+23°`,
  но остаётся «купаться можно» — округление для показа не сдвигает порог
  на градус (закрыто тестом).
- Подписи волнения словами («штиль», «лёгкая рябь», «небольшая волна»,
  «заметное волнение», «сильное волнение») и сводка `warmest` — самый
  тёплый курорт, единственное, что нужно туристу поверх списка.
- Блок «🌊 Море и купание» на главной: карточки курортов с цветным
  вердиктом и дисклеймером, что у берега вода может быть прохладнее
  (модель считает открытую воду).
- Кэш `MARINE_TTL` (3 часа) — дольше погодного: волновую модель
  обновляют раз в 12 часов, температуру воды раз в сутки.
- Тесты: 209 → **272 Python**. Новый модуль `test_sea.py` (54 теста):
  пороги воды и волны, подписи, вердикт по сырым значениям, разбор
  ответа Open-Meteo Marine, мусор вместо чисел (`null`, строки, `bool`),
  кэш и `refresh`, фильтр по точке, `warmest`, 404-контракт.
  Плюс четыре теста ассетов: блок на главной подключён к `/api/sea`,
  вердикт не продублирован во фронте, волна без данных не выдумывается.

### Changed

- Версия 1.2.0 → **1.3.0**; кэш PWA `crimea-gid-v1.3.0`.
- Список морских точек — `SEA_POINTS` (15 приморских курортов).
  Симферополь, Бахчисарай и Белогорск остались без точек: моря у них нет,
  и `/api/sea?city=simferopol` отвечает `404` «город без выхода к морю»,
  а не пустым списком. Согласованность с `CITIES` держат тесты.
- `fmtTemp()` в `app.js` — единая запись температуры (`+23°`, `—` при
  отсутствии данных) для погоды и моря.

### Docs

- `docs/api.md`: раздел `GET /api/sea` с таблицей вердиктов и объяснением,
  почему индекс считается на сервере; 404 для материковых курортов.
- `docs/architecture.md`: компонент `marine.py`, поток данных моря,
  строка в таблице кэшей и в матрице офлайн-режимов.
- `docs/development.md`: `test_sea.py` в таблицах, `SEA_POINTS` и пороги
  вердикта в «Как расширять», счётчики тестов.
- README: блок возможностей, `/api/sea` и `MARINE_TTL` в таблицах,
  починена разъехавшаяся таблица API (строки уезжали под абзац).

## [1.2.0] — 2026-09-17

Фаза «Точность данных и шаринг избранного» ([ROADMAP](ROADMAP.md)):
фильтр «открыто сейчас» перестал огрублять сезонные границы до месяца,
а избранное стало шариться ссылкой.

### Added

- **Дневная точность расписаний** (`firstDay`/`lastDay` в `schedule`,
  `static/open-now.js`): «16 июня» больше не скругляется до начала
  месяца. Точные границы получили Ливадия («16 июня–15 октября»),
  Массандра («июль–14 сентября») и Воронцовский дворец
  («16 сентября»): у края сезона окно теперь правильное. Вне всех
  окон подпись показывает точную дату открытия: «Закрыто · открывается
  16 июня» / «открывается в мае». Нечитаемые дневные границы деградируют
  до месячного поведения, без падения.
- **Шаринг избранного** (`static/favs-link.js`, маршрут
  `#/favs?f=id1,id2`): кнопка «🔗 Ссылка на избранное» в блоке
  «В избранном» копирует ссылку; получатель одним тапом добавляет эти
  места к своему избранному. Признаются только id, которые есть в
  каталоге получателя; ссылка только добавляет — своё избранное она
  не чистит. Мусор и чужие форматы slug тихо отбрасываются.
- Счётчик избранного по-русски: «1 место / 2 места / 5 мест».
- `ruff format` для всего репо (17 файлов: app, tests, tools) и шаг
  `ruff format --check app tests tools` в CI; версия ruff закреплена
  в `requirements-dev.txt`, чтобы формат не дрейфовал.
- Тесты: 206 → **209 Python** и 33 → **48 JS**. Новые: двусторонняя
  сверка дневных границ `schedule` с датировками в `hours` (допущена
  одна неявная граница — день после конца соседнего окна), дневные
  границы и зимние диапазоны в `open-now`, дата открытия в подписи
  вне сезона, 9 тестов `favs-link` (round-trip, мусор, known-ids) и
  два теста аудита (UMD/проводка, однонаправленный импорт).

### Changed

- Версия 1.1.0 → **1.2.0**; кэш PWA `crimea-gid-v1.2.0`.
- Подпись вне сезона: «Закрыто · открывается <дата>» вместо общего
  «Закрыто в этом сезоне» (старое оставлено фолбэком на битые
  расписания).
- CI: новый шаг `ruff format --check`; `node --check` теперь включает
  `favs-link.js`.

### Docs

- `docs/data.md`: `firstDay`/`lastDay` в схеме `schedule` (пример —
  Ливадия), правило сверки границ с текстом, «точность — до дня».
- `docs/development.md`: `favs-link.test.js` в таблицах, формат ruff,

## [1.1.0] — 2026-09-17

Фаза «После релиза» ([ROADMAP](ROADMAP.md)): то, что стало видно на
полном каталоге — скорость первого экрана и польза от часов работы.

### Added

- **Порционный показ каталога** (`static/catalog-page.js`): первый рендер
  рисует 12 карточек вместо 60, остальное догружается при прокрутке
  (`IntersectionObserver` с запасом 400 px) или по кнопке «Показать ещё».
  Кнопка — не декорация: это доступный путь без скролла и фолбэк для
  браузеров без `IntersectionObserver`. Догрузка дорисовывает порцию
  через `insertAdjacentHTML`, а не перерисовывает сетку.
- **Фильтр «🕘 Открыто сейчас»** (`static/open-now.js`) и парное полю
  `hours` машинное расписание `schedule` у всех 19 объектов. Время
  считается по Крыму (UTC+3) независимо от пояса устройства. Места без
  расписания (пляжи, мысы) фильтр **не прячет** — они открыты всегда.
  Статус показывается подписью в карточке и в модалке.
- `hours` + `schedule` ещё у 6 объектов: Мангуп-Кале, Эски-Кермен,
  Неаполь Скифский, Судакская крепость, Калос-Лимен, аквариум Алушты
  (13 → **19**).
- Флаг `open=1` в ссылке на подборку (`catalog-link.js`).
- Тесты: 192 → **206 Python** и 14 → **33 JS**. Среди них — сверка
  времён `schedule` с текстом `hours`, покрытие всех 12 месяцев,
  идемпотентность `bindCards` и поведение фильтра на границах окна.

### Fixed

- `bindCards` вешала обработчики повторно: при догрузке порции старые
  карточки получали второй listener, и «сердечко» избранного
  переключалось дважды, то есть не работало вовсе. Теперь привязка
  идемпотентна (`data-bound`).

### Changed

- Версия 1.0.0 → **1.1.0**; кэш PWA `crimea-gid-v1.1.0`.
- `state.f` каталога получил поле `open`; наблюдатель догрузки
  отключается при уходе с маршрута каталога.
- CI проверяет синтаксис новых модулей.

### Docs

- `docs/data.md`: поле `schedule`, таблица ключей, правила заполнения
  и честная оговорка про точность до месяца.
- README и `docs/development.md`: новые модули, фильтр, счётчики тестов.

## [0.12.0] — 2026-09-16

Фаза «Фронт и доступность» ([ROADMAP](ROADMAP.md)). Поведение для

### Added

- Доступность: skip-link «Перейти к содержимому», focus trap в модалке
  с возвратом фокуса на инициатора, `aria-live` у тостов и анонс маршрутов
  (`#route-status`), осмысленные `alt` категорийных картинок,
  `aria-current="page"` в навигации, `aria-pressed` у избранного и чипов;
  карточки, остановки плана и точки карты открываются с клавиатуры
  (ссылки `#/place/<id>`, Enter/Space на маркерах SVG); видимый
  клавиатурный фокус (`:focus-visible`).
- Фильтры каталога в URL (`#/catalog?tag=&area=&q=&sort=`): подборка
  копируется кнопкой «🔗 Ссылка на подборку» и воспроизводится у получателя.
  Сериализация — `static/catalog-link.js` (UMD) + 8 JS-тестов.
- Open Graph / Twitter Card: `og:*`/`twitter:*` в каркасе; `GET /`
  подставляет фактический origin в `og:url`/`og:image` (`SITE_ORIGIN`
  из env или `X-Forwarded-Proto`/`X-Forwarded-Host`).
- `Content-Security-Policy` в заголовках всех ответов
  (`script-src 'self'`, `object-src 'none'`, `frame-ancestors 'self'`,
  ослабление через `CSP_FRAME_ANCESTORS`); inline-обработчики убраны —
  аварии картинок ведёт делегированный listener по `data-img-fallback`.
- `tests/test_assets.py` — аудит статики: бюджет веса и размеры картинок,
  запрет inline-обработчиков и пустых `alt`, внешние `<script>`,
  согласованность SW/манифеста.
- `tools/optimize_images.py` — dev-ресайз картинок (Pillow, идемпотентный,
  режим `--check`); в рантайм-зависимости не входит.
