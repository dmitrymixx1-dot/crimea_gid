# Справочник REST API

Базовый URL: `/api`. Все ответы — JSON в UTF-8.
Интерактивная OpenAPI-документация FastAPI: `/docs`, `/redoc`.

Общие заголовки ответов (middleware безопасности):

```
X-Content-Type-Options: nosniff
Referrer-Policy: strict-origin-when-cross-origin
Content-Security-Policy: default-src 'self'; script-src 'self';
  style-src 'self' 'unsafe-inline'; img-src 'self' data:; connect-src 'self';
  font-src 'self' data:; object-src 'none'; base-uri 'self';
  form-action 'self'; frame-ancestors 'self'
```

CSP допускает inline только для стилей (style-атрибуты шаблонов):
весь JavaScript приложения — внешние файлы (`script-src 'self'`),
inline-обработчики вида `onerror=` во фронтенде запрещены и закрыты
тестом `test_assets.py::test_no_inline_event_handlers_in_frontend`.
`frame-ancestors` ослабляется переменной `CSP_FRAME_ANCESTORS`
(например, `*` для встраивания в iframe-превью).

## GET /api/health

Живость сервиса и версия приложения. Используется Docker-healthcheck'ом
и фронтендом (бейдж версии в подвале).

**Ответ 200:**

```json
{"ok": true, "name": "Крым.Гид", "version": "1.11.0"}
```

| Поле | Тип | Описание |
|---|---|---|
| `ok` | bool | всегда `true`, если сервер отвечает |
| `name` | string | имя приложения |
| `version` | string | версия (semver, `MAJOR.MINOR.PATCH[-суффикс]`) |

## GET /api/limits

Бюджеты дорогих ручек и счётчики текущего процесса. Ручка **бесплатная**
(лимитом не закрыта): смысл её в том и состоит, чтобы настроить лимиты
по факту, а не на глаз.

**Ответ 200:**

```json
{
  "enabled": true,
  "rules": [
    {"name": "quiz", "method": "POST", "path": "/api/quiz/evaluate",
     "limit": 30, "window": 60, "hint": "оценка перебирает весь каталог"},
    {"name": "news", "method": "GET", "path": "/api/news",
     "limit": 6, "window": 300, "hint": "11 источников на запрос, кнопка «Обновить» у человека"},
    {"name": "weather", "method": "GET", "path": "/api/weather",
     "limit": 4, "window": 900, "hint": "18 городов на запрос, модель обновляется раз в час"},
    {"name": "sea", "method": "GET", "path": "/api/sea",
     "limit": 3, "window": 1800, "hint": "15 точек на запрос, волновую модель обновляют раз в 12 часов"}
  ],
  "total": {"name": "total", "method": "*", "path": "*",
            "limit": 120, "window": 600,
            "hint": "потолок на клиента поверх бюджетов ручек: все дорогие запросы"},
  "stats": {"news": {"allowed": 12, "denied": 1},
            "total": {"allowed": 12, "denied": 0}},
  "clients": 7,
  "counters": 9
}
```

| Поле | Тип | Описание |
|---|---|---|
| `enabled` | bool | включены ли лимиты (`RATE_LIMIT_ENABLED`) |
| `rules[].name` | string | имя правила: то же, что в заголовке `X-RateLimit-Rule` |
| `rules[].limit`, `rules[].window` | int | сколько запросов разрешено и за сколько секунд |
| `rules[].hint` | string | почему бюджет такой — по нему его и настраивают |
| `total` | object\|null | общий потолок клиента поверх ручек (`null`, если `RATE_LIMIT_TOTAL=0`); `method`/`path` — `*`, потому что к маршруту он не привязан |
| `stats` | object | сколько запросов пущено и отбито, по правилам и по потолку, суммарно по всем клиентам |
| `clients` | int | сколько разных клиентов сейчас в памяти лимитера |
| `counters` | int | сколько счётчиков они занимают: на клиента их несколько (по одному на тронутую ручку плюс потолок) |

Адреса клиентов наружу не отдаются: счётчики складываются по правилам.
Числа живут в памяти процесса — рестарт их обнуляет (как и сами лимиты).
Отказ чужого бюджета в `stats` не пишется: `denied` у ленты означает,
что клиента отбила именно лента, а не общий потолок.

## GET /api/tags

Словари тегов и типов мест. Фронтенд строит по ним фильтры, чипы,
легенду карты и эмодзи категорий.

**Ответ 200:**

```json
{
  "tags": {"beach": "пляжи", "wine": "вино", "...": "..."},
  "types": {
    "winery": {"emoji": "🍷", "label": "Вина", "img": "cat_wine.jpg"},
    "...": {}
  }
}
```

| Поле | Тип | Описание |
|---|---|---|
| `tags` | object | `id тега → русское название` (15 тегов) |
| `types` | object | `id типа → {emoji, label, img}`; `img` — файл в `/static/img/` |

Список тегов и типов: [data.md](data.md#справочники).

## GET /api/attractions

Каталог мест с фильтрами. Все элементы содержат координаты `lat`/`lng`
(используются схемой-картой).

**Параметры запроса** (все необязательные, комбинируются логическим И):

| Параметр | Тип | Описание |
|---|---|---|
| `tag` | string | оставить места, у которых есть этот тег (напр. `wine`) |
| `area` | string | географический район (напр. `Восточный`, URL-encoded) |
| `q` | string | подстрока в названии или описании (регистр не важен) |

**Пример:** `GET /api/attractions?tag=beach&area=Южный+берег&q=пляж`

**Ответ 200:**

```json
{
  "count": 60,
  "items": [
    {
      "id": "aipetri",
      "name": "Ай-Петри: канатная дорога и плато",
      "type": "nature",
      "region": "Ялта → Ай-Петри, 1234 м",
      "area": "Южный берег",
      "description": "7-минутный подъём канаткой…",
      "tags": ["view", "active", "photo", "nature"],
      "season": ["spring", "summer", "autumn"],
      "budget": 1,
      "duration_h": 4,
      "rating": 4.7,
      "price": 1000,
      "price_hint": "канатка ~1000 ₽ туда-обратно",
      "tips": "Берите ветровку…",
      "access": "both",
      "lat": 44.45,
      "lng": 34.06
    }
  ]
}
```

Поля элемента — см. [data.md → attractions.json](data.md#attractionsjson).
Все поля обязательны, кроме пары `hours` + `schedule`: они приходят
только у объектов с публикуемым расписанием — дворцов, музеев, пещер
и парков (19 из 60). У пляжей и природных точек этих полей в ответе нет.
`hours` — текст для человека, `schedule` — его машинная проекция
(`[{"months": "4-10", "from": "09:00", "to": "18:00", "closed": ["mon"]}]`),
по которой фронтенд считает «открыто сейчас». Так же устроена пара
`price` + `price_hint`: `price` — минимальная цена входа (0 — бесплатно),
`budget` (1–3) — полоса самой дорогой цены из подсказки; правило и его
двусторонние тесты — в [data.md](data.md#цена-и-уровень-из-одной-строки).
`price` решает, когда эконому честно сказать «дороже, чем ваш бюджет»,
а `budget` = 3 — что за место стоит премиум-впечатление.

## POST /api/quiz/evaluate

Ответы квиза → профиль отдыха, ранжированные рекомендации,
план по дням, подсказка по логистике и новости по интересам.

Результат детерминирован: одни и те же ответы → один и тот же набор
(новости могут отличаться — лента живая).

**Тело запроса** (все поля необязательные; пустое тело валидно):

```json
{
  "purpose": ["beach", "photo"],
  "season": "summer",
  "tempo": "relax",
  "budget": "comfort",
  "party": "couple",
  "duration": "3-5",
  "transport": "car"
}
```

| Поле | Тип | Значения | По умолчанию |
|---|---|---|---|
| `purpose` | string[] | id тегов (неизвестные отбрасываются), макс. 3 | `["beach"]` |
| `season` | string | `summer` `spring` `autumn` `winter` `any` | `any` |
| `tempo` | string | `relax` `medium` `active` | `medium` |
| `budget` | string | `economy` `comfort` `premium`; потолок эконома — 1 000 ₽, комфорта — 3 000 ₽, премиум без потолка (те же числа, что в подсказках квиза) | `comfort` |
| `party` | string | `solo` `couple` `family` `friends` | `solo` |
| `duration` | string | `1-2` `3-5` `6-10` `10+` | `3-5` |
| `transport` | string | `car` `transit` | `car` |

**Ответ 200** (фрагменты):

```json
{
  "profile": {"title": "Море, солнце и спокойствие", "emoji": "🌅", "summary": "…"},
  "answers": {"purpose": ["beach", "photo"], "…": "…"},
  "count": 8,
  "days_hint": "3-5",
  "all_matched": 24,
  "recommendations": [
    {"id": "…", "name": "…", "score": 7.9,
     "reasons": ["Совпадает: пляжи"], "type_meta": {"emoji": "🏖️", "…": "…"}}
  ],
  "itinerary": {
    "n_days": 4,
    "days": [
      {"day": 1, "area": "Южный берег", "area_label": "Южный берег",
       "tags": ["beach", "view"],
       "stops": [
         {"id": "…", "name": "…", "slot": "morning", "duration_h": 3}
       ]}
    ],
    "reserve": [{"id": "…", "name": "…"}]
  },
  "news": [{"title": "…", "crimea_score": 4, "topics": ["beach"]}],
  "transport_hint": "🚗 На машине можно заехать…"
}
```

Семантика ключевых полей:

| Поле | Описание |
|---|---|
| `profile` | выбранный по первому интересу («профиль отдыха») |
| `count` / `all_matched` | сколько мест в выдаче / сколько всего прошло порог |
| `recommendations[].score` | итоговый балл места (как считается — [architecture.md](architecture.md#матчинг)) |
| `recommendations[].reasons` | человекочитаемые объяснения «почему» |
| `itinerary.days[].stops[].slot` | `morning` `afternoon` `evening` `full` |
| `itinerary.reserve` | подошедшие места, не влезшие в дни («запас на дождь») |
| `news` | до 4 крымских новостей по темам интересов |

**Ответ 422** — невалидное тело: неверный тип поля (например, `purpose`
не список) или значение вне `id` опций `quiz.json` (например,
`season: "never"`). Пустой `purpose` валиден — трактуется как `["beach"]`.

## GET /api/news

Лента новостей: агрегат RSS-источников и публичных телеграм-каналов
с фильтром «про Крым», классификацией тем и кэшированием.

**Параметры запроса:**

| Параметр | Тип | По умолчанию | Описание |
|---|---|---|---|
| `limit` | int | 40 | сколько элементов вернуть (1–100) |
| `refresh` | bool | false | `1` — игнорировать кэш и перечитать источники |

> ⚠️ `refresh=1` дёргает все внешние источники (до `NEWS_HTTP_TIMEOUT`
> секунд на источник). Не используйте в циклах.

**Ответ 200:**

```json
{
  "online": true,
  "updated_at": "2026-09-15T22:00:00+03:00",
  "sources": [{"id": "tass", "name": "ТАСС"}, {"id": "tg-rbc", "name": "РБК · TG"}],
  "failed_sources": ["News.ru · TG"],
  "total": 80,
  "crimea_total": 16,
  "items": [
    {
      "id": "n0",
      "title": "В Крыму продлили купальный сезон",
      "link": "https://…",
      "summary": "…",
      "published": "2026-09-15T18:40:00+03:00",
      "source": "ТАСС",
      "source_id": "tass",
      "crimea_score": 6,
      "topics": ["beach", "weather"]
    }
  ]
}
```

| Поле | Описание |
|---|---|
| `online` | `true` — хотя бы один источник ответил; `false` — показан кэш/офлайн-снапшот |
| `failed_sources` | имена источников, не ответивших при последнем опросе |
| `total` / `crimea_total` | всего элементов / из них про Крым (`crimea_score > 0`) |
| `items[].crimea_score` | баллы «крымскости» (маркеры городов и географии) |
| `items[].topics` | до 3 тем: `safety` `transport` `beach` `weather` `nature` `events` `food` `history` |
| `items[].id` | `n<N>` — живые элементы, `s<N>` — из офлайн-снапшота |

В офлайн-режиме элементы снапшота могут содержать флаг `sample: true`
(демонстрационные материалы — фронтенд их помечает).

## GET /api/weather

Погода по курортам (Open-Meteo, без ключа), кэш на час.

**Параметры запроса:**

| Параметр | Тип | По умолчанию | Описание |
|---|---|---|---|
| `city` | string | — | id города (напр. `yalta`); неизвестный id → `404` |
| `refresh` | bool | false | `1` — игнорировать часовой кэш |

**Ответ 200:**

```json
{
  "online": true,
  "updated_at": "2026-09-15T22:10:00+03:00",
  "cities": [
    {
      "id": "yalta",
      "name": "Ялта",
      "available": true,
      "current": {"temp": 22, "emoji": "🌤️", "label": "в основном ясно", "wind": 12},
      "forecast": [
        {"day": "Ср", "emoji": "🌤️", "max": 26, "min": 17},
        {"day": "Чт", "emoji": "⛅", "max": 25, "min": 16}
      ],
      "hourly": [
        {"t": "2026-09-15T22:00", "temp": 22, "emoji": "🌤️", "precip": 5},
        {"t": "2026-09-15T23:00", "temp": 21, "emoji": "⛅", "precip": 40}
      ]
    },
    {"id": "kerch", "name": "Керчь", "available": false}
  ]
}
```

Погодные коды — WMO (`current.label` — русская подпись; полный словарь —
`WMO` в `app/services/weather.py`). `online: false` + `available: false`,
если Open-Meteo недостижим — фронтенд в этом случае прячет виджет.
Список городов — константа `CITIES` (18 курортов).

**Почасовой прогноз** (`hourly`) — до `HOURLY_HOURS` (24) значений вперёд,
начиная с текущего часа города:

| Поле | Тип | Описание |
|---|---|---|
| `hourly[].t` | string | локальное время города, `2026-09-15T22:00` |
| `hourly[].temp` | int \| null | °C, округлено (банковское округление) |
| `hourly[].emoji` | string | эмодзи WMO-кода (`🌡️` — код неизвестен) |
| `hourly[].precip` | int \| null | вероятность осадков, % |

Времена — локальные для города (`timezone=auto`), и сервер не переводит
их в пояс клиента: окно отсчитывается сравнением ISO-строк от
`current.time`. **Какое окно показать, решает клиент** (`static/hourly.js`
по крымскому времени): ответ живёт в кэше до `WEATHER_TTL`, и «сейчас»
в нём успевает устареть. Окно, оставшееся в прошлом целиком, отдаётся
пустым списком — фронт прячет блок, а не показывает вчерашние часы.

**Ответ 404** — неизвестный `city`:

```json
{"detail": "город «gotham» не найден"}
```

## GET /api/sea

Купальный индекс: температура поверхности воды и волна у приморских
курортов (Open-Meteo Marine, без ключа), кэш 3 часа — волновую модель
обновляют раз в 12 часов, температуру воды раз в сутки.

**Параметры запроса:**

| Параметр | Тип | По умолчанию | Описание |
|---|---|---|---|
| `city` | string | — | id курорта (напр. `yalta`); неизвестный id → `404` |
| `refresh` | bool | false | `1` — игнорировать кэш |

**Ответ 200:**

```json
{
  "online": true,
  "updated_at": "2026-09-17T12:00:00+03:00",
  "warmest": {"id": "kerch", "name": "Керчь", "temp": 24},
  "points": [
    {
      "id": "yalta",
      "name": "Ялта",
      "available": true,
      "water_temp": 23,
      "wave_height": 0.3,
      "wave_label": "лёгкая рябь",
      "verdict": {"code": "comfort", "emoji": "🏊", "label": "купаться комфортно"}
    },
    {"id": "kerch", "name": "Керчь", "available": false}
  ]
}
```

**Купальный вердикт считает сервер** (`app/services/marine.py`), а не
фронтенд: он не зависит от часового пояса устройства, и все клиенты видят
один ответ. Пороги сравниваются с «сырыми» значениями модели, а не
с округлёнными для показа: 22.6 °C показывается как `+23°`, но вердикт
остаётся «купаться можно». Волна важнее температуры — безопасность выше
удовольствия:

| Условие | `code` | Подпись |
|---|---|---|
| волна ≥ 1,5 м | `danger` | «купаться опасно: волна 1,6 м» |
| волна ≥ 1,0 м | `rough` | «купаться не стоит: волна 1,2 м» |
| вода ≥ 23 °C | `comfort` | «купаться комфортно» |
| вода ≥ 20 °C | `ok` | «купаться можно» |
| вода ≥ 16 °C | `cool` | «прохладно — для закалённых» |
| вода < 16 °C | `cold` | «холодно: купание для моржей» |
| нет данных о воде | `no_data` | «нет данных о воде» |

`wave_label` — словесная подпись волнения (штиль, лёгкая рябь, небольшая
волна, заметное волнение, сильное волнение): без неё «0,3 м» ничего
не говорит. `warmest` — самый тёплый из доступных курортов или `null`.

Список точек — константа `SEA_POINTS` (`app/services/marine.py`), 15
курортов. Координаты вынесены на 1–8 км от берега в открытую воду:
морская модель считает только по воде. Симферополь, Бахчисарай и
Белогорск в списке отсутствуют — моря у них нет, и запрос
`/api/sea?city=simferopol` отвечает `404` с пояснением причины, а не
пустым списком. `online: false` + `available: false`, если Open-Meteo
Marine недостижим, — фронтенд в этом случае честно пишет, что данных нет.

**Ответ 404** — неизвестная или материковая точка:

```json
{"detail": "город «simferopol» без выхода к морю"}
```

## Служебные маршруты

| Метод | Путь | Описание |
|---|---|---|
| GET | `/` | SPA-каркас: `index.html` с подставленным origin в Open Graph |
| GET | `/static/*` | статика (JS/CSS/изображения, манифест PWA) |
| GET | `/static/i18n/en.json` | английский пакет интерфейса (словарь подписей + переводы каталога по id места) |
| GET | `/sw.js` | service worker из корня (scope `/`), `Cache-Control: no-cache` |

`GET /` отдаёт каркас с мета-тегами Open Graph / Twitter Card: плейсхолдер
`__ORIGIN__` заменяется фактическим origin запроса (с учётом
`X-Forwarded-Proto`/`X-Forwarded-Host`) или значением `SITE_ORIGIN` из env —
`og:url` и `og:image` обязаны быть абсолютными. Ответ — `text/html`,
заголовки безопасности те же.

Локализация — тоже статика, а не API: `static/i18n.js` умеет говорить по-
русски без всякого файла, а английский пакет `GET /static/i18n/en.json`
(~62 КБ, его отдаёт `StaticFiles`) фронт качает только при включённом
английском — `?lang=en`, сохранённый выбор или настройки браузера. Бюджет
лимита при этом не расходуется: маршрут бесплатный, как и чтение каталога.
Новый язык — ещё один файл в `static/i18n/`; сервер о речи не знает.

## GET /static/i18n/en.json

Английский пакет интерфейса. Это файл в `StaticFiles`, а не эндпоинт:
схемы ответа не гарантирует, кэшируется service worker’ом как статика и
лимитом не считается. Русская речь его не читает вовсе.

```json
{
  "lang": "en",
  "name": "English",
  "ui": { "Каталог мест": "Places" },
  "labels": { "крепости": "fortresses", "через {n} минут": "in {n} minutes" },
  "places": {
    "lastochino": {
      "name": "Swallow's Nest",
      "region": "Yalta · Ai-Todor cape",
      "description": "…",
      "tips": "…",
      "price_hint": "castle ticket ~500 ₽",
      "hours": "10:00–19:00 (May–October), …"
    }
  }
}
```

| Ключ | Что покрывает | Проверка |
|---|---|---|
| `ui` | строки каркаса и `t()`-шаблоны `app.js` | двусторонняя: ни дыр, ни мёртвых ключей (`test_i18n.py`) |
| `labels` | подписи из данных и модулей (теги, типы, профили, погода, море, «открыто сейчас», лимиты) | полнота обязательного списка + JS-тесты модулей |
| `places` | карточки каталога по id места | id и поля совпадают с `attractions.json` |

Формат ключа — русская строка ровно так, как её видит DOM: пробелы схлопнуты,
числовые группы свёрнуты в `{n}` («Показано {n} из {n}»). Брендовое
«Крым.Гид» внутри строк не переводится.

## Ограничение частоты запросов

Дорогие ручки закрыты лимитом **на клиента** (`app/ratelimit.py`): квиз
перебирает весь каталог, а `?refresh=1` заставляет сервис идти во внешние
источники. Всё остальное — каталог, health, статика, чтение из кэша —
считается бесплатным: обычный просмотр лимит не расходует.

Бюджет у каждой ручки **свой** — по тому, как часто её данные меняются
и кто её зовёт; общее число на все три refresh-ручки заставляло равняться
на самую дорогую.

| Правило | Ручка | Лимит | Окно | Env |
|---|---|---|---|---|
| `quiz` | `POST /api/quiz/evaluate` | 30 | 60 с | `RATE_LIMIT_QUIZ`, `RATE_LIMIT_QUIZ_WINDOW` |
| `news` | `GET /api/news?refresh=1` | 6 | 300 с | `RATE_LIMIT_NEWS`, `RATE_LIMIT_NEWS_WINDOW` |
| `weather` | `GET /api/weather?refresh=1` | 4 | 900 с | `RATE_LIMIT_WEATHER`, `RATE_LIMIT_WEATHER_WINDOW` |
| `sea` | `GET /api/sea?refresh=1` | 3 | 1800 с | `RATE_LIMIT_SEA`, `RATE_LIMIT_SEA_WINDOW` |
| `total` | все четыре выше | 120 | 600 с | `RATE_LIMIT_TOTAL`, `RATE_LIMIT_TOTAL_WINDOW` |

Откуда числа: ленту обновляют кнопкой в интерфейсе (11 источников,
кэш 15 минут) — бюджет щедрее; погоду и море дёргают программно, а их
данные меняются редко (модель погоды — раз в час, волновая — раз в
12 часов), поэтому окна длиннее. Переопределяется каждая ручка отдельно;
старая общая переменная `RATE_LIMIT_REFRESH` (+`_WINDOW`) работает
фолбэком для всех трёх refresh-ручек, если своя не задана.

**Общий потолок клиента** (`total`) лежит поверх раздельных бюджетов.
Раздельные окна защищают ручку, но не процесс: клиент, который берёт
«по чуть-чуть» с каждой ручки, в сумме даёт заметную нагрузку — за 10
минут бюджеты ручек позволили бы ему ~320 дорогих запросов, а потолок
режет ровно эту «размазанную» нагрузку (120 за то же окно). Живой
человек за сессию делает единицы дорогих запросов, поэтому его потолок
не задевает. `RATE_LIMIT_TOTAL=0` выключает его, оставляя бюджеты ручек.

Запрос проходит, только если место есть **в обоих** счётчиках, и отказ
потолка не тратит слот ручки: данных клиент не получил, значит и бюджет
ручки не израсходован. `Retry-After` на таком отказе покрывает самое
долгое ожидание, чтобы клиент не вернулся ровно за следующим `429`.

Окно **скользящее** (журнал времён запросов), а не фиксированное: на его
границе клиент не получает второй лимит подряд. Счётчики живут в памяти
процесса — базы у проекта нет, рестарт их обнуляет. Число счётчиков
ограничено (`RATE_LIMIT_MAX_KEYS`, 5000): на одного клиента их несколько
(по одному на тронутую ручку плюс потолок), и самые давние вытесняются,
так что память не растёт бесконечно.

**Сколько на самом деле просят** видно в [GET /api/limits](#get-apilimits)
(числа процесса) и в логе: каждый отказ `429` пишется строкой вида
`429 news: клиент 203.0.113.7 исчерпал бюджет 6 за 300 с`, а отказ общего
потолка — `429 total: клиент 203.0.113.7 исчерпал бюджет 120 за 600 с`
(`docker compose logs app`) — по ним бюджеты и подкручивают.

**Кто считается клиентом.** За своим reverse-proxy (Caddy из
`docker-compose.yml`) адрес соединения — сам прокси, поэтому compose
передаёт `TRUST_PROXY=1`, и приложение берёт первый адрес из
`X-Forwarded-For`. Без прокси (`TRUST_PROXY=0`, дефолт `config.py`)
считается адрес соединения: чужому клиенту заголовок верить нельзя,
он подделывается одной строкой.

**Заголовки** приходят на лимитируемых ручках и на успехе, и на отказе:

```
X-RateLimit-Rule: news       # чей это бюджет (см. таблицу выше)
X-RateLimit-Limit: 6
X-RateLimit-Remaining: 4
X-RateLimit-Reset: 300       # секунд до полного очищения окна
X-RateLimit-Total-Limit: 120      # общий потолок клиента (если включён)
X-RateLimit-Total-Remaining: 117
X-RateLimit-Total-Reset: 600
Retry-After: 40              # только на 429
```

Имя правила нужно потому, что бюджетов несколько: без него клиент
не понял бы, остаток какой ручки он прочитал. Основные заголовки
описывают **связавший** бюджет — на успехе это ручка, а на отказе тот,
кто отказал; когда клиента отбил общий потолок, приходит
`X-RateLimit-Rule: total`. Потолок дополнительно виден в своих
`X-RateLimit-Total-*`: окна у ручки и у потолка разные, и смешать их
в одной тройке чисел значит соврать клиенту.

Фронт этим и пользуется — складывает бюджеты по правилам, показывает
«осталось 4 обновления из 6» рядом с кнопкой «↻ Обновить» и гасит её
на время окна вместо того, чтобы выбивать второй `429`; исчерпанный
потолок гасит кнопку так же, а подпись меняется на «обновления
исчерпаны» (`static/rate-limit.js`, `coolDown` и `budgetHint` в `app.js`).

**Ответ 429:**

```json
{"detail": "слишком часто: попробуйте через 40 с"}
```

Клиент не выдумывает время ожидания, а показывает `Retry-After`
(`static/rate-limit.js` превращает его в «попробуйте через 2 минуты»).
Лимиты отключаются полностью: `RATE_LIMIT_ENABLED=0`.

## Коды ошибок

| Код | Когда |
|---|---|
| 404 | неизвестный `/api/*` маршрут; `/api/attractions/{id}` с несуществующим id; `/api/weather?city=` с неизвестным id; `/api/sea?city=` с неизвестным id (в т.ч. с материковым курортом) |
| 405 | метод не поддерживается маршрутом (например, POST на GET-эндпоинт) |
| 422 | невалидные параметры запроса/тела (тип, диапазон `limit`, значение вне опций квиза) |
| 429 | превышен бюджет дорогой ручки (`POST /api/quiz/evaluate`, `?refresh=1`) или общий потолок клиента; ответ несёт `Retry-After`, `X-RateLimit-*` и `X-RateLimit-Rule` с именем исчерпанного бюджета (`total` — когда отбил потолок) |
| 500 | непредвиденная ошибка (внешние сервисы сами по себе 500 не вызывают — они переводят ленту/погоду/море в офлайн) |
