# Архитектура «Крым.Гид»

## Принципы

1. **Без базы данных** — контент живёт в читаемых человеком JSON
   (`app/data/`). Правка каталога не требует миграций и деплоя кода.
2. **Без внешних ключей** — все внешние данные из публичных источников:
   RSS-ленты, превью телеграм-каналов, Open-Meteo.
3. **Деградация, а не падение** — недоступность сети переводит ленту
   и погоду в офлайн-режим, приложение остаётся работоспособным.
4. **Тонкий фронтенд без сборки** — vanilla JS, hash-роутинг,
   никаких npm-зависимостей.

## Компоненты

```
app/
├── main.py               # FastAPI: маршруты, middleware безопасности, SPA
├── config.py             # константы, переменные окружения, версия
└── services/
    ├── load.py           # загрузка JSON-данных (lru_cache)
    ├── recommend.py      # квиз → баллы → рекомендации → план по дням
    ├── news.py           # агрегация RSS+Telegram → фильтр «Крым» → темы → кэш
    └── weather.py        # Open-Meteo → нормализация → часовой кэш

static/
├── index.html            # каркас (шапка, <main id="view">, футер, OG-теги)
├── app.js                # SPA: роутер, состояние, рендер-функции, PWA
├── plan-link.js          # UMD: сериализация плана в ссылку (тестируется)
├── catalog-link.js       # UMD: фильтры каталога ↔ URL (тестируется)
├── style.css             # стили + @media print + a11y (skip-link, sr-only)
├── sw.js                 # service worker (офлайн-оболочка)
└── manifest.webmanifest  # PWA-манифест
```

## Потоки данных

### Квиз → рекомендации → план

```
SPA ──POST /api/quiz/evaluate──► main.py
                                  │ evaluate(answers, news_items)
                                  ▼
                            recommend.py
              ┌───────────────┬─┴───────────────┬──────────────┐
              ▼               ▼                 ▼              ▼
        _score_attraction  profile       plan_itinerary    news-фильтр
        (баллы + причины)  (по 1-му      (кластеры по      (по темам
                            интересу)     районам, слоты)   интересов)
```

### Матчинг

Каждое место набирает баллы по ответам квиза (`_score_attraction`):

| Фактор | Баллы |
|---|---|
| Совпадение тега с интересом | `+3.0` за тег (главный вклад) |
| Сезон совпал / не совпал | `+1.5` / `−1.0` |
| Бюджет места ≤ бюджета гостя | `+1.0`, иначе `−2.0` + причина |
| Компания (семья/пара/друзья) | `+1.0…+1.5` по правилам |
| Темп (relax/active) | `+0.5` по правилам |
| Без машины + место «только на авто» | `−3.0` |
| Рейтинг выше 4.0 | `+(rating − 4.0)` |

В выдачу попадают места с баллом `≥ 2.5`; сортировка по убыванию.
Число мест = `DAYS_BY_DURATION[duration]` (5/8/12/16).

**Планировщик** (`plan_itinerary`) раскладывает топ по дням
(`ITINERARY_DAYS`: 2/4/7/12): выбирает район с наибольшим остатком мест,
набирает до 3 остановок суммарно ≤7 часов, места `duration_h ≥ 6`
занимают день целиком (`slot: full`). Короткая последняя остановка
(≤2.5 ч) становится вечерней. Остаток — в `reserve` («запас на дождь»).

### Новости

```
sources.json ──► NewsService.get(force?) 
                  │
                  ├─ кэш в памяти свеж? ──► payload()
                  │
                  ▼ asyncio.gather (параллельно, таймаут NEWS_HTTP_TIMEOUT)
        ┌─────────────────────┬──────────────────────┐
        ▼ RSS                 ▼ Telegram             ▼ всё упало
   feedparser           parse_telegram_page     _snapshot_items()
   (title/link/         (t.me/s/<канал>,        (news_snapshot.json,
    summary/date)        regex по widget-разметке) без сети)
        └─────────────────────┴──────────────────────┘
                  ▼ _normalize()
        crimea_score (маркеры городов/географии)
        match_topics (regex-правила по приоритету)
        дедупликация по нормализованному заголовку
        сортировка: Крым ↑, внутри — свежие ↑, cap MAX_NEWS_ITEMS
                  ▼
        кэш в памяти + файл cache/news_cache.json (переживает рестарт)
```

- **Две ступени кэша**: память (`NEWS_CACHE_TTL`, по умолчанию 15 мин)
  и файл (хранится до `4 × NEWS_CACHE_TTL`, подхватывается после рестарта).
- **Офлайн-ветка**: если ни один источник не ответил — показывается
  снапшот, фронт получает `online: false` и рисует бейдж «офлайн».
- **User-Agent** — строго ASCII: httpx кодирует заголовки latin-1,
  кириллица молча ломала все запросы (регрессия закрыта тестом
  `test_user_agent_is_ascii`).

### Погода

```
WeatherService.get(city?, refresh?)
  │ miss в кэше (WEATHER_TTL, 1 час)
  ▼ asyncio.gather по 18 городам
Open-Meteo: current (temp/code/wind) + daily ×4 (code/max/min)
  ▼ нормализация: WMO-код → (эмодзи, русская подпись),
    день недели из локальной даты прогноза, округление °C
```

Исключение по одному городу помечает его `available: false`,
остальные продолжают работать; `online: false` только если упали все.

## Кэширование: сводная таблица

| Слой | Что | TTL | Переживает рестарт |
|---|---|---|---|
| Память (`NewsService._cache`) | лента | `NEWS_CACHE_TTL` (15 мин) | нет |
| Файл (`cache/news_cache.json`) | последняя лента | `4 × NEWS_CACHE_TTL` | да |
| Память (`WeatherService._cache`) | погода по городам | `WEATHER_TTL` (1 час) | нет |
| `lru_cache` (load.py) | JSON-данные | процесс | нет |
| Service worker | статика + последние API-ответы | до смены версии `CACHE` | да (в браузере) |
| `localStorage` (браузер) | избранное | бессрочно | да |

## Офлайн-режимы (матрица)

| Компонент | Есть сеть | Нет сети |
|---|---|---|
| Каталог/квиз/карта | полные данные из своих JSON | те же (они локальные) |
| Новости | live-опрос источников | кэш → снапшот + бейдж «офлайн» |
| Погода | live Open-Meteo | `online:false`, виджет прячется |
| SPA-оболочка | — | service worker (после 1-го визита) |

## Фронтенд

- **Роутинг**: hash (`#/`, `#/catalog`, `#/map`, `#/quiz`, `#/news`,
  `#/place/<id>`). Параметры: `?plan=` (восстановление результата квиза
  по ссылке) и `?tag=&area=&q=&sort=` у каталога.
- **Фильтры каталога в URL**: при входе по ссылке фильтры читаются из
  адреса (`CatalogLink.parseCatalogQuery`), дальше состояние живёт в
  `state.f` и зеркалится в адрес через `history.replaceState` (без спама
  в истории). Кнопка «🔗 Ссылка на подборку» копирует абсолютный URL.
- **Доступность**: skip-link (preventDefault + `focus()` на `<main
  tabindex="-1">`, hash не меняется и роутер не сбивается), focus trap
  в модалке (`role="dialog" aria-modal`, Tab/Shift+Tab цикличны, фокус
  возвращается на инициатора), `aria-live` у тостов и анонс маршрута
  в `#route-status`, осмысленные `alt` категорийных картинок, карточки/
  остановки плана/точки карты открываются с клавиатуры (ссылки
  `#/place/<id>` и Enter/Space на маркерах SVG).
- **Состояние**: единый объект `state` в `app.js` (каталог, мета, новости,
  фильтры, прогресс квиза, результат, избранное, погода, флаг маршрута).
- **Избранное**: `localStorage["crimea_favs"]`, рендерится сердечками,
  кольцами на карте и блоком на главной.
- **Шеринг плана**: ответы квиза сериализуются в
  `purpose~season~tempo~budget~party~duration~transport` в `#/quiz?plan=…`;
  получатель ссылки проходит «авто-оценку» без вопросов.
- **Печать**: `body.print-plan` + `@media print` — виден только план.

## PWA

- `manifest.webmanifest` + иконки 180/192/512 + `theme-color`.
- `/sw.js` из корня (scope `/`): **статика** — cache-first с фоновым
  обновлением, **API** — network-first с откатом в кэш.
- Имя кэша версионируется (`crimea-gid-vX.Y.Z`) — при обновлении
  приложения старые кэши зачищаются в `activate`.
- Precache хранит отрендеренный ответ `GET /` (с абсолютными OG-тегами),
  а не сырой `index.html` с плейсхолдером `__ORIGIN__`.

## Безопасность

- Middleware: `X-Content-Type-Options: nosniff`, `Referrer-Policy`,
  `Content-Security-Policy` (`default-src 'self'`, `script-src 'self'`,
  `object-src 'none'`, `frame-ancestors 'self'` по умолчанию). Inline
  допустим только в style-атрибутах (`style-src 'unsafe-inline'`), поэтому
  аварийные обработчики картинок — один делегированный listener на
  `data-img-fallback`, а не `onerror=` в разметке.
- Фронтенд экранирует значения из данных и новостей при сборке шаблонов
  (`esc()`); внешний контент дополнительно проходит очистку: `_clean_text`
  срезает HTML-теги и HTML-сущности новостей перед отдачей.
- Ссылки на внешние источники — `target="_blank" rel="noopener"`.
- Open Graph: `og:url`/`og:image` абсолютные — origin берётся из
  `SITE_ORIGIN` (env) или из запроса с учётом `X-Forwarded-Proto/Host`.
- Секретов в репозитории нет (API-ключи не нужны принципиально).
  Прод-настройки (`DOMAIN`, `ACME_EMAIL`) живут в `.env`, который
  исключён из Git и образа; в репозитории — только `.env.example`.

## Развёртывание

Прод-схема — два контейнера, описанных в `docker-compose.yml`:

```
Интернет ──:443──► caddy ──reverse_proxy──► app:8000 ──► app/data/*.json
                     │                        │
             caddy-data (сертификаты)   news-cache (том /srv/cache)
```

- **Caddy** терминирует HTTPS и сам выпускает сертификат по ACME —
  принцип «без ключей» выдержан и в деплое. Он же передаёт
  `X-Forwarded-Proto/Host`, из которых собираются абсолютные OG-теги.
- **Приложение** наружу не публикуется (`expose`, не `ports`):
  единственная точка входа — прокси.
- **Состояние** — только файловый кэш ленты в томе `news-cache`.
  Данные некритичные (при потере лента пересобирается из источников),
  но бэкапятся скриптами `deploy/backup-cache.sh` / `restore-cache.sh`
  ради быстрого переезда. Контент лежит в Git и бэкапа не требует.

Полный рантайм-гид — [deploy.md](deploy.md).
